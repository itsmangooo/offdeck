# OFFDECK v0.3

| Milestone | Acceptance check |
| --- | --- |
| 1. Five-card hands | Three independent clients start and refill to five, complete a match, and exercise reconnects. |
| 2. Adult content direction | Review an original sample spanning all six themes and play it in the existing game. |
| 3. Library | Validate 250 scenarios and 750 responses, review the writing and load the library in a live room. |
| 4. Match decks | Draw 20 unique scenarios by default and finish only after the selected deck runs out. |
| 5. Rotation | Exercise back-to-back decks, category variety, response-pile recycling and bounded room history. |
| 6. Readability | Inspect short, medium and long cards in the hand, inspection, voting and results at three desktop sizes. |
| 7. Age confirmation | Verify first visit, decline, acceptance, reload, direct invitations and eligibility enforcement. |
| 8. Regression | Run all tests, including a three-client match, rematches, reconnects and eight-player simulations. |
| 9. Release | Update controls, README and version, verify the production build and publish the public tag. |

## Verification record

- **1. Five-card hands** passed 17 unit/integration tests and three production Playwright tests. Three separate contexts completed the physical-card match and kept four cards plus one replacement between rounds. The physical-card and room tests exercised refresh recovery and host migration. Inspected the live 1440 x 900 five-card table.
- **2. Adult direction** replaced the default release deck during development with an editorial pass across six topics. Seventeen automated checks passed, and three production browser clients completed a match with the new writing. Inspected the scenario, submissions and scoring in the running 3D table.
- **3. Card library** reviewed all six groups, revised weak and redundant phrasing, and verified 250 scenarios plus 750 responses. The 20 Node tests passed, including structural rejection and near-duplicate checks. Three browser contexts finished a production match using real cards drawn from the expanded library.
- **4. Match decks** passed an eight-player, 20-round simulation with no repeated scenario and exact final scores. Three browser clients connected to the default server, each showing one active scenario, 19 in the deck and a five-card hand. The three-round production fixture still completed and allowed a rematch.
- **5. Rotation** passed 23 automated tests. Eight players completed six consecutive 20-scenario matches with three or four cards per category and no adjacent repeat. A 43-response pool tested drawing new cards before recycling and keeping every active hand unique. Three browser clients completed the physical match and verified a fresh scenario and hands on rematch.
- **6. Readability** verified short, medium and long library responses and the longest scenario with three production clients at 1280 x 720, 1440 x 900 and 1920 x 1080. Inspected hand hover, close-up scenario inspection, voting and results. The browser test measured canvas text bounds and cast votes using the physical cards. All 23 Node tests and both focused Playwright tests passed.
- **7. Age confirmation** inspected the warning in Chrome and checked the decline, invite, acceptance and reload flows. No game WebSocket opened before acceptance. The server rejects sockets without the self-declaration. Twenty-four Node tests and three dedicated browser tests passed.
- **8. Regression** passed all 24 Node tests and all 20 production Chromium tests. Three independent browsers completed one match and two rematches with nine distinct scenarios and no repeated response across matches. Five- and eight-client rounds stayed synchronized. Selection disconnect, reconnect during voting, host migration, private hands, ties and automatic exhaustion passed. The 1440 x 900 Medium benchmark on the GTX 1660 SUPER measured 60 FPS, 16.8 ms p95, 105 draw calls per frame and 22.12 MiB of tracked 2D texture storage.
