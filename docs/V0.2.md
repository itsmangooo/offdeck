# OFFDECK v0.2

A milestone closes after the feature runs in the production build, relevant tests pass, and the visual result has been inspected. Verification uses the same match rules as v0.1.

| Milestone | Verification gate |
| --- | --- |
| 1. Seated camera | Inspect selection and voting from center, diagonal and end seats. Check all eight seat poses, camera bounds, scenario inspection and reduced motion. |
| 2. Card layout | Inspect seven-card hands and 3-, 5- and 8-card voting layouts at 1280×720, 1440×900 and 1920×1080. Exercise physical cards and verify long text. |
| 3. Avatars | Inspect remote heads, names and private backs around the table. Verify visible status changes and submission origins on live clients. |
| 4. Room | Compare the poker room with v0.1, check contact and lighting, test graphics levels and remeasure the scene. |
| 5. HUD | Inspect selection, voting and results at desktop sizes. Check visibility, keyboard controls, settings and room controls. |
| 6. Motion | Verify the sequence of deal, submission, reveal and discard on real clients, including refresh and reduced motion. |
| 7. Voting and results | Exercise anonymous voting, acknowledgement, point changes, ties, final results and rematch. |
| 8. Menu and lobby | Test navigation, invitations, ready/host indicators, feedback and keyboard operation. |
| 9. Regression | Complete a three-player match, exercise five and eight seats and run reconnect/migration cases. Inspect all specified viewports and compare performance. |
| 10. Release | Capture seven production screenshots, update documentation and version, then verify the public GitHub release and tag. |

## Verification record

- **1. Camera** — Verified all eight camera poses at three aspect ratios. Inspected center, diagonal and end-seat frames, including the 1920×1080 end seat. Three production browser scenarios passed, including inspection by click and keyboard, direct card interaction, and a complete match. The hardware v0.1 baseline was 60.0 FPS, 16.80 ms p95, 119 draw calls per frame and 27 live textures at 1440×900 on the GTX 1660 SUPER. The end-seat frame exposed existing fan trimming to address in milestone 2.
- **2. Cards** — Verified 16 Node tests and production Playwright layout checks at 1280×720, 1440×900 and 1920×1080. Projection tests covered every seat and 2–8 visible response cards. Inspected real 3-, 5- and 8-player captures, corrected physical rail occlusion in the held hand, and confirmed each response had its own hit target. The three-client match still reached deck exhaustion and replayed.
- **3. Avatars** — Verified placement on all eight seats, photographed private fans, submission motion and disconnected labels, and tested seat resume on independent clients. The per-player status carries participation flags only. Authorship remains absent from vote snapshots. Five production browser scenarios and 17 Node tests passed.
- **4. Room** — Inspected the stitched rail, woven felt, reflective trim, floor contact and paneled clubhouse in the menu and in a live match. Five production browser scenarios and all 17 Node tests passed. Low/Medium/High produced 1036×648, 1440×900 and 1800×1125 render buffers at the same viewport. All three measured 60.0 FPS and 16.80 ms p95 on the GTX 1660 SUPER. The medium scene used 123 draws per frame and 32 live textures, versus 119 and 27 in v0.1.
- **5. HUD** — Inspected edge-aligned phase and score panels and room controls at all three desktop sizes. Production checks exercised scenario visibility, keyboard access, settings focus, and the selection, voting and results HUD. The full three-client physical match and all 17 Node tests passed.
- **6. Motion** — Inspected the shuffled opening pack, deal, remote submission flight and anonymous flip sequence with hardware motion enabled. Production tests exercised automatic replacement and round progression, a resumed voting seat with an immediately usable card, and reduced-motion controls. Four browser scenarios, the build and 17 Node tests passed.
- **7. Outcomes** — Inspected the voter-only physical confirmation, score increments, result banner and ranked final panel. Three production browser scenarios covered immediate confirmation, duplicate and own-card rules, a three-way tie at rank 1, a single winner, synchronized scores and replay. The build and 17 Node tests passed.
- **8. Navigation** — Inspected the refreshed menu and lobby with seated guests. Five production browser scenarios verified nested-dialog keyboard focus, clipboard accuracy, pasted invites, ready status, host migration, active leave confirmation, expired rooms and stored settings. The build and 17 Node tests passed.
